Honda Pet Travel Safety System

Team-led, Honda-sponsored embedded system for monitoring in-car conditions and protecting pets during short unattended periods.

Capstone Design Showcase demo with the Honda-sponsored team prototype.

Overview

This project is about solving a very real problem. Leaving pets in cars is dangerous, but people still do it, often without realizing how fast conditions can change. I led a Honda-sponsored senior design project to build an embedded system that mounts in a vehicle, monitors cabin conditions, and lets the owner check in and respond when things become unsafe.

The current prototype runs on a single ESP32-S3 and integrates a BME280 environmental sensor, a cooling fan, and a camera. Data is sent over Wi-Fi to a dashboard that works on both web and mobile, so the owner can see cabin conditions and control the fan in real time.

Architecture

The architecture is intentionally simple so the system is reliable and easy to duplicate. The ESP32-S3 reads temperature, humidity, and pressure from the BME280 and publishes those readings over Wi-Fi using MQTT. At the same time, the ESP32-S3 streams live video from the camera through its local IP address. The dashboard subscribes to the MQTT data to display cabin readings and provides fan control with ON/OFF/AUTO modes. In AUTO mode, the fan turns on when temperature exceeds a set threshold and turns off once it drops below it.

Most up-to-date system flow: ESP32-S3 + BME280 + fan + camera over Wi-Fi to MQTT/HTTP and a web dashboard.

My Role

  • Led a 5-person team and owned the system direction across embedded, networking, web, and mechanical work.
  • Wrote embedded C/C++ on ESP32-S3 for sensor reading, fan control logic, and camera streaming setup.
  • Built the telemetry + dashboard pipeline using MQTT over Wi-Fi and a React UI.
  • Designed the enclosure in SOLIDWORKS and iterated using 3D printing for physical prototype demos.

This project was a full-stack embedded build. I had to think like a firmware engineer, a web developer, and a product designer at the same time, while also coordinating milestones and sponsor-facing demos.

Testing Highlights

We focused on proving the prototype works in realistic conditions, especially for live monitoring and reliability.

  • Video streaming: 20–30 FPS under ideal conditions, 10–15 FPS under network congestion.
  • Latency behavior: internal processing stayed fast, with perceived performance mostly limited by Wi-Fi bandwidth.
  • Reliability: system ran for extended periods without failure during long-duration tests.
  • Fan control: fan behavior followed dashboard modes and AUTO threshold logic consistently.

Next Steps

The next phase is making the prototype more vehicle-ready and polished.

  • Add the 12 V to 5 V power path so the device can run directly from a vehicle outlet.
  • Measure power draw across operating modes to confirm safe usage on a 12 V supply.
  • Improve the dashboard UI and tighten the mobile experience.
  • Continue enclosure iteration for mounting, airflow direction, and sensor placement inside a real vehicle.

The goal is to make this feel like a real product. Something a driver could actually trust when they leave their pet in the car for “just a minute.”
